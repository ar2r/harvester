# Инструкции по работе с LedgerFox

## Обзор проекта

- LedgerFox — Go-приложение (Go 1.24+): задача `lkdr` собирает чеки ФНС «Мои чеки онлайн» в SQLite, stdin-триггер даёт ручной запуск. Точка входа: `cmd/app/main.go`.
- Ключевые пакеты: `internal/jobs` (реестр задач + `lkdr`), `internal/triggers/stdin`, `internal/database` (GORM, только SQLite, запись через UPSERT), `internal/captcha` (RuCaptcha), `internal/mocklkdr` (мок API ФНС для тестов).
- Документация: `README.md` и `docs/` (`getting-started.md`, `configuration.md`, `development.md`, `lkdr-report.md`).
- Python-отчёты (`scripts/reports/*.py`) работают с SQLite-базой LKDR отдельно от Go-приложения; `make report` — интерактивное меню отчётов (раздел «Python-отчёты»).
- Сверять документацию с текущим кодом; не перезаписывать чужие правки.

## Архитектурные факты

- Конфигурация — viper: JSON-файл (`--config.file`), переменные окружения, CLI-флаги (пути совпадают с ключами: `--stdin.user=all`).
- Поднимаются только модули с `enabled: true`; ошибка любого включённого модуля на старте — `panic` (fail-fast).
- Одна и та же job для одного пользователя не выполняется параллельно (`MultiMutex`); разные jobs и пользователи — параллельно. Идентификатор `all` у jobIDs запускает все jobs.
- Запуск только ручной: интерактивный stdin или однократный `--stdin.user=<id|all>` (`make parse` — `all`: все пользователи по алфавиту, ошибка одного не прерывает остальных, итоговый код 1). Планировщика нет — периодичность через внешний cron; SMS в фоне не спросить, авторизоваться заранее.
- Неофициальное API ФНС: изменения на стороне сервиса могут ломать сбор.
- Вывод: текстовый по умолчанию; `--json` — весь вывод построчным JSON (принудительно `log.encoding=json`); `--debug` — уровень DEBUG. В тексте задач результат включает пользователя: ` ✔ a/lkdr`.

## Команды разработки

- `make build` / `make bin` — сборка в `bin/` (`app`, `mocklkdr`); `make test` — `go test -v ./...` + автотесты Python-отчётов (`scripts/tests/`); одиночный тест: `go test -v ./path/to/pkg -run TestName`.
- Тесты: `internal/jobs/jobs_test.go`, `batch_test.go`, `internal/triggers/stdin/trigger_test.go`, `internal/jobs/lkdr/internal/loaders/{receipts,fiscal_data}_test.go`; интеграционные — `internal/jobs/lkdr/integration_test.go` (мок подменяет ФНС через redirect-транспорт; отдельно мок запускается `docker compose up mocklkdr` → `lkdr.apiUrl`). Новую логику сопровождать тестами.
- `scripts/dist.sh` — релизные архивы в `bin/` (кросс-сборка требует C-компилятор из-за SQLite/CGO).

## Безопасность и приватность

- `config.json`, локальные БД (`*.db`) и отчёты (`reports/`, `lkdr-report.txt`) содержат персональные данные и секреты: не коммитить и не переносить содержимое в инструкции, коммиты и логи проверки. Все перечисленное уже в `.gitignore`.
- Не фиксировать в скриптах, правилах категорий, AI-промптах, тестах, примерах и документации репозитория ничего, что может указывать на конкретные личные покупки и операции: приёмы врачей, медикаменты, анализы и прочее, что пользователи не хотят видеть в отчётах. Маркеры категорий — только обобщённые основы слов (`лекар-`, `капл-`, `анализ-`), без названий конкретных препаратов, диагнозов и клиник из реальных баз. Если такое название нужно привести или вывести — использовать завуалированные обобщённые названия («аптечные товары», «медуслуги») или синтетические нейтральные примеры; в логах проверки реальные названия таких товаров не печатать. В отчётах товары приватных категорий (по умолчанию «Аптека и здоровье», `reports.privateCategories`) не выводятся построчно — видна только сумма по категории.

## Автоматические коммиты

- После каждого логически законченного изменения и подходящей проверки создавать локальный Git-коммит без повторного подтверждения; явно указывать файлы, не включать чужие изменения (при чужих staged-изменениях коммитить ограниченно: `git commit -m … -- <файлы>`). После коммита проверять состав и сообщать короткий хеш.
- После каждого коммита делать push текущей ветки в `origin` (постоянное указание пользователя от 2026-10-03). Повторное подтверждение не требуется. Если push не удался (сеть, авторизация, отклонение non-fast-forward) — сообщить пользователю и продолжить работу без принудительного push (`--force` запрещён).

## Загрузка чеков

```bash
make parse
./bin/app --config.file=./config.json --stdin.user=all
```

- `internal/jobs/lkdr/job.go`: сначала загрузчик `Receipts`, затем `FiscalData`.
- `receipts.go`: инкремент от последнего `receive_date` телефона; первая синхронизация — за 12 месяцев (по умолчанию), с `lkdr.firstSyncFrom` (дата YYYY-MM-DD) или за `firstSyncMonths` последних месяцев у пользователя (приоритет: firstSyncMonths > firstSyncFrom; отрицательные месяцы и неверные даты — ошибка старта); UPSERT чеков и брендов.
- `fiscal_data.go`: дозагрузка отсутствующих деталей и позиций; `receipt.fiscal.data.unavailable` — до 5 пропусков за запуск, следующий останавливает загрузчик; отсутствующие данные и известная внутренняя ошибка API пропускаются.
- Отчёт сам не синхронизирует ФНС: для актуальных данных сначала запустить загрузку.

## Python-отчёты

Python 3.10+, только стандартная библиотека. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python scripts/reports/lkdr_report.py --db lkdr.db --days 30 --top 10
PATH="$PWD/.venv/bin:$PATH" make lkdr-report
```

- Меню `make report` (`scripts/report.py`): автодискавери `scripts/reports/*.py`; id = имя файла; `_`-префикс — служебные, в меню не попадают; заголовок меню = первая строка docstring скрипта. Без меню: `./scripts/report.py <id> [args]`, `--list`. Без интерактива вообще: `make report-all` = ai-report (HTML месяца) + lkdr-report-ai (текстовый отчёт с AI-выводами и рекомендациями в консоль).
- Новые отчёты: копировать `scripts/reports/_template.py` (как добавлять — docs/development.md, раздел «Python-отчёты»); пример по правилам — `scripts/reports/example.py`. Автотесты отчётов — `scripts/tests/test_reports.py` (unittest; запускаются `make test` вместе с Go-тестами, поэтому `make test` требует python3).
- HTML-отчёт месяца: `make ai-report` → `scripts/reports/ai_report.py` рендерит шаблон `scripts/templates/lkdr-report.html` в `reports/lkdr-YYYY-MM.html` (месяц = конец периода: свежий чек или `--as-of`; перезапуск обновляет файл месяца; расчёты переиспользует `lkdr_report.py`). Повторяемые блоки шаблона обрамлены маркерами `<!-- block:name -->`…`<!-- /block:name -->` — правки вёрстки делать внутри блоков, сохраняя маркеры. AI-карточки — JSON от AI CLI (агент — `ai.command` в config.json, по умолчанию codex; `--no-ai` отключить); фолбэк — детерминированные карточки из данных.

- Обязательные таблицы: `receipts`, `brands`, `fiscal_data`, `fiscal_data_items`; перед запуском проверять существование БД.
- Конец периода — `max(fiscal_data.date_time)` (переопределяется `--as-of`); текущий период сравнивается с предыдущим той же длины, обе границы включены.
- Расчёты: для положительных операций эффективный расход `max(total_sum - prepaid_sum, 0)`; `operation_type` 2 и 3 — отрицательные на полный `total_sum`; закрытия предоплаты не увеличивают расходы. Товарные суммы и количества — со знаком операции; товарная разбивка может расходиться с итогом чеков.
- Категории — `CATEGORY_RULES` по первому совпадению подстроки, без совпадения «Прочее». Валюты: по умолчанию RUB, текстовые признаки Казахстана — KZT; не складываются. Приоритет переопределения: `--currency-receipt`, `--currency-store`, эвристика.
- Названия товаров при выводе (таблицы обоих отчётов, AI-промпты) сокращаются до `reports.maxItemNameChars` из config.json (по умолчанию 40, целое ≥ 1, иначе ошибка запуска; резолв — `_config.load_max_item_name_chars`). Только отображение: агрегация и ключи — по полным названиям.
- Приватные категории: `reports.privateCategories` (по умолчанию `["Аптека и здоровье"]`, пустой список отключает; резолв — `_config.load_private_categories`) — товары этих категорий не выводятся построчно в отчётах и не попадают в AI-промпты, сумма видна только на уровне категории.
- Повторяющиеся покупки: положительный итог, количество > 1 и больше одного чека; сервисные строки исключаются по `SERVICE_ITEM_MARKERS`.
- AI-выводы (`--ai-summary`) вызывают внешний AI CLI — по умолчанию `codex exec --sandbox read-only`; агент настраивается `ai.command` в config.json (полная командная строка с аргументами, промпт — на stdin; резолв — `scripts/reports/_config.py::load_ai_command`, флаг `--ai-command` переопределяет). Таймаут 180 с на вызов, ошибка AI не ломает отчёт. В prompt — агрегаты и контекст семьи из 2 взрослых и 2 подростков; менять контекст — в `build_ai_prompt`.
- Шаблон-прототип HTML-отчёта: `scripts/templates/lkdr-report.html` — полный каркас (структура секций + стили) с плейсхолдерами `{{ … }}` и без реальных сумм и персональных данных; безопасен для коммита. HTML-отчёты и правки их вёрстки делать по этому шаблону; готовые отчёты с реальными данными — только в `reports/` (gitignored).
- Для проверки обычного отчёта достаточно запуска без AI с `--color never`; личные покупки не публиковать в логах.
