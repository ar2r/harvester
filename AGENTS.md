# Инструкции по работе с LedgerFox

## Обзор проекта

- LedgerFox — Go-приложение (Go 1.24+): задача `lkdr` собирает чеки ФНС «Мои чеки онлайн» в SQLite, stdin-триггер даёт ручной запуск. Точка входа: `cmd/app/main.go`.
- Ключевые пакеты: `internal/jobs` (реестр задач + `lkdr`), `internal/triggers/stdin`, `internal/database` (GORM, только SQLite, запись через UPSERT), `internal/captcha` (RuCaptcha), `internal/mocklkdr` (мок API ФНС для тестов).
- Документация: `README.md` и `docs/` (`getting-started.md`, `configuration.md`, `development.md`, `lkdr-report.md`).
- Python-отчёт `scripts/lkdr_report.py` работает с SQLite-базой LKDR отдельно от Go-приложения.
- Сверять документацию с текущим кодом; не перезаписывать чужие правки.

## Архитектурные факты

- Конфигурация — viper: JSON-файл (`--config.file`), переменные окружения, CLI-флаги (пути совпадают с ключами: `--stdin.user=all`).
- Поднимаются только модули с `enabled: true`; ошибка любого включённого модуля на старте — `panic` (fail-fast).
- Одна и та же job для одного пользователя не выполняется параллельно (`MultiMutex`); разные jobs и пользователи — параллельно. Идентификатор `all` у jobIDs запускает все jobs.
- Запуск только ручной: интерактивный stdin или однократный `--stdin.user=<id|all>` (`make parse` — `all`: все пользователи по алфавиту, ошибка одного не прерывает остальных, итоговый код 1). Планировщика нет — периодичность через внешний cron; SMS в фоне не спросить, авторизоваться заранее.
- Неофициальное API ФНС: изменения на стороне сервиса могут ломать сбор.
- Вывод: текстовый по умолчанию; `--json` — весь вывод построчным JSON (принудительно `log.encoding=json`); `--debug` — уровень DEBUG. В тексте задач результат включает пользователя: ` ✔ a/lkdr`.

## Команды разработки

- `make build` / `make bin` — сборка в `bin/` (`app`, `mocklkdr`); `make test` — `go test -v ./...`; одиночный тест: `go test -v ./path/to/pkg -run TestName`.
- Тесты: `internal/jobs/jobs_test.go`, `batch_test.go`, `internal/triggers/stdin/trigger_test.go`, `internal/jobs/lkdr/internal/loaders/{receipts,fiscal_data}_test.go`; интеграционные — `internal/jobs/lkdr/integration_test.go` (мок подменяет ФНС через redirect-транспорт; отдельно мок запускается `docker compose up mocklkdr` → `lkdr.apiUrl`). Новую логику сопровождать тестами.
- `scripts/dist.sh` — релизные архивы в `bin/` (кросс-сборка требует C-компилятор из-за SQLite/CGO).

## Безопасность и приватность

## Загрузка чеков

```bash
make parse
./bin/app --config.file=./config.json --stdin.user=all
```

- `internal/jobs/lkdr/job.go`: сначала загрузчик `Receipts`, затем `FiscalData`.
- `receipts.go`: инкремент от последнего `receive_date` телефона, первая синхронизация — за 12 месяцев или с `firstSyncFrom` (дата YYYY-MM-DD в конфиге, валидируется при старте); UPSERT чеков и брендов.
- `fiscal_data.go`: дозагрузка отсутствующих деталей и позиций; `receipt.fiscal.data.unavailable` — до 5 пропусков за запуск, следующий останавливает загрузчик; отсутствующие данные и известная внутренняя ошибка API пропускаются.
- Отчёт сам не синхронизирует ФНС: для актуальных данных сначала запустить загрузку.

## Python-отчёт

Python 3.10+, только стандартная библиотека. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python scripts/lkdr_report.py --db lkdr.db --days 30 --top 10
PATH="$PWD/.venv/bin:$PATH" make lkdr-report
```

- Обязательные таблицы: `receipts`, `brands`, `fiscal_data`, `fiscal_data_items`; перед запуском проверять существование БД.
- Конец периода — `max(fiscal_data.date_time)` (переопределяется `--as-of`); текущий период сравнивается с предыдущим той же длины, обе границы включены.
- Расчёты: для положительных операций эффективный расход `max(total_sum - prepaid_sum, 0)`; `operation_type` 2 и 3 — отрицательные на полный `total_sum`; закрытия предоплаты не увеличивают расходы. Товарные суммы и количества — со знаком операции; товарная разбивка может расходиться с итогом чеков.
- Категории — `CATEGORY_RULES` по первому совпадению подстроки, без совпадения «Прочее». Валюты: по умолчанию RUB, текстовые признаки Казахстана — KZT; не складываются. Приоритет переопределения: `--currency-receipt`, `--currency-store`, эвристика.
- Повторяющиеся покупки: положительный итог, количество > 1 и больше одного чека; сервисные строки исключаются по `SERVICE_ITEM_MARKERS`.
- AI-выводы (`--ai-summary`) вызывают внешний Codex CLI (`codex exec --sandbox read-only`); таймаут 180 с на вызов, ошибка AI не ломает отчёт. В prompt — агрегаты и контекст семьи из 2 взрослых и 2 подростков; менять контекст — в `build_ai_prompt`.
- Шаблон-прототип HTML-отчёта: `scripts/templates/lkdr-report.html` — полный каркас (структура секций + стили) с плейсхолдерами `{{ … }}` и без реальных сумм и персональных данных; безопасен для коммита. HTML-отчёты и правки их вёрстки делать по этому шаблону; готовые отчёты с реальными данными — только в `reports/` (gitignored).
- Для проверки обычного отчёта достаточно запуска без AI с `--color never`; личные покупки не публиковать в логах.
