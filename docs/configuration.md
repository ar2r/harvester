# Конфигурация

Справочник по `config.json` LedgerFox.

Конфигурация загружается через [viper](https://github.com/spf13/viper) в порядке
приоритета: CLI-флаги → переменные окружения → JSON-файл (`--config.file=config.json`).
Каждому ключу соответствует флаг с тем же путём (`--stdin.user=all`, `--lkdr.apiUrl=…`).
Подсистема включается секцией с `enabled: true`; ошибка любого включённого модуля
на старте — паника.

## Формат вывода

По умолчанию — текстовый режим для человека: логи в `stderr` с коротким временем,
результаты задач в консоль (` ✔ default/lkdr` / ` ✘ default/lkdr: …`).

- `--json` (корневой ключ `json`) — весь вывод построчным JSON: логи в `stderr`,
  события триггера (`{"event":"job","status":"ok","user":"default","job":"lkdr"}`) в
  `stdout`. Принудительно включает `log.encoding=json`.
- `--debug` (ключ `debug`) — уровень логирования `DEBUG` вместо `INFO`: детальные
  записи о записи в БД и объёмах обработанных данных. Переопределяет `log.level`.
- Флаги комбинируются: `--debug --json`.

## Минимальный пример

```json
{
  "stdin": { "enabled": true },
  "captcha": { "rucaptchaKey": "<API-ключ>" },
  "lkdr": {
    "enabled": true,
    "database": { "dsn": "lkdr.db" },
    "users": {
      "default": [{ "phone": "79001234567" }]
    }
  }
}
```

## Блоки

### log

| Параметр | Тип | Описание |
|----------|-----|----------|
| `level` | string | Уровень логирования: `DEBUG`, `INFO`, `WARN`, `ERROR` (по умолчанию `INFO`). |
| `encoding` | string | Формат логов: `text` или `json` (по умолчанию `text`). |
| `addSource` | boolean | Добавлять номера строк исходника. |

### stdin

| Параметр | Тип | Описание |
|----------|-----|----------|
| `enabled` | boolean | Включение триггера. |
| `user` | string | ID пользователя для однократного запуска без ввода; `all` — по очереди все пользователи из конфигурации (порядок по алфавиту, ошибка одного не прерывает остальных). Пусто — интерактивный режим. |

### lkdr

| Параметр | Тип | Описание |
|----------|-----|----------|
| `enabled` | boolean | Включает задачу. |
| `apiUrl` | string | Базовый URL API. По умолчанию — сервис ФНС; для тестов — адрес мок-сервиса ([Разработка](development.md#интеграционные-тесты-и-мок-сервис)). |
| `batchSize` | integer | Чеков в одном запросе и фискальных данных за одно обновление (по умолчанию 1000). |
| `maxRequests` | integer | Максимум запросов выгрузки за один запуск для каждого загрузчика (страница чеков, запрос фискальных данных). `0` — без ограничения (по умолчанию). Прерывание по лимиту — не ошибка: следующий запуск продолжит с места остановки. Для живого теста с урезанным объёмом: `--lkdr.maxRequests=2 --lkdr.batchSize=10`. |
| `timeout` | string | Таймаут запросов (по умолчанию `5m`). |
| `database` | object | `{ "dsn": "…" }` — путь к файлу базы SQLite. |
| `users` | object | Пользователи и их авторизационные данные. |

Загрузка чеков: самая первая синхронизация телефона качает последние 12
месяцев, каждый следующий запуск — только новые чеки от самого свежего
загруженного; настроек глубины нет. Загруженная история остаётся в базе
независимо от запусков.

Поля пользователя: `phone` (обязательный, формат `7XXXXXXXXXX`);
`deviceId` и `userAgent` — для авторизации и обновления токена. `deviceId` при
отсутствии генерируется автоматически; значения можно подсмотреть в браузере при
попытке авторизации. Токены привязаны к `deviceId` — при смене потребуется
повторная авторизация.

```json
"users": {
  "default": [{ "phone": "79001234567" }]
}
```

### captcha

| Параметр | Тип | Описание |
|----------|-----|----------|
| `rucaptchaKey` | string | API-ключ [rucaptcha.com](https://rucaptcha.com) для автоматического решения капчи. Нужен для первой авторизации: без него задача падает с ошибкой `authorizer is required, but not set`. |

### ai

AI CLI-агент для AI-выводов Python-отчётов (`make ai-report`, `--ai-summary`
текстового отчёта). Go-приложение секцию игнорирует.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `command` | string | Командная строка агента с аргументами; промпт передаётся ему на stdin. По умолчанию `codex exec --color never --sandbox read-only -`. Флаг `--ai-command` у отчётов переопределяет значение. |

Пример для другого агента:

```json
"ai": { "command": "claude -p" }
```

### reports

Параметры вывода Python-отчётов; Go-приложение секцию игнорирует.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `maxItemNameChars` | integer | До скольких символов сокращать названия товаров в отчётах, а в текстовом отчёте — и названия магазинов (по умолчанию 40). Целое число ≥ 1; неверное значение — ошибка запуска отчёта. Сокращение влияет только на отображение: агрегация считается по полным названиям; HTML-отчёт выводит названия магазинов целиком. |
| `privateCategories` | array | Категории, товары которых не выводятся в отчётах построчно и не попадают в AI-промпты — видна только сумма по категории (приватные покупки: аптечка, врачи, анализы, гигиена). Список названий категорий; пустой список `[]` отключает скрытие. По умолчанию `["Аптека и здоровье", "Косметика и гигиена"]`. |

Пример:

```json
"reports": { "maxItemNameChars": 40, "privateCategories": ["Аптека и здоровье", "Косметика и гигиена"] }
```

## Безопасность

`config.json` содержит токены и привязки пользователей в открытом виде: ограничьте
доступ к файлу, не коммитьте и не переносите его содержимое в документацию и логи.
